# 互动规则

Air 状态、动画和气泡分别管理。她可以继续工作，同时保留一次性托付的未读报告；对话表情结束后回到当前状态。拖拽和飞行期间不抢动作。

| 场景 | 表现 |
| --- | --- |
| Air 明确需要输入 | 优先催促；点击后改为轻等，不代答任务 |
| 还有已观察任务运行 | 继续工作，不因另一对话完成而庆祝 |
| 全部已观察任务连续空闲 2 秒且有完成事件 | 合并报信，文字最多保留 5 分钟，点击收起，新任务开始让位 |
| “全部忙完再叫我” | 使用同一完成条件，减少过程闲聊；输入请求仍催促 |
| “接下来谁先完成就叫我” | 接受后第一个完成只报告一次；其他任务继续工作，气泡保持原 5 分钟期限 |
| 原生 DSH 有任务、Air 无活动 | 回到原作的 DSH 联动 |
| 主动聊天 | 工作身体仍跟随，外部文字暂时让位；输入优先 |

一次性托付不认接受之前的旧事件，不绑定排队中的下一项或某个对话。改口、取消、超时或重启可解除。最后整批完成可更新报告；若兑现时已全部空闲，则不紧接着重复报一次。点击只确认当前实例的气泡，拖拽松手不算已读。

自然语言退场约 5 秒后执行，新的对话可以取消待执行退场；隐藏状态由原配置持久保存。使用原设置页配置的显示热键或 `toggle-pet.ps1` 召回。模型只获得显示、留下、回复、查询、提醒等受限动作，不获得 shell 或 Air 任务控制权。

触屏按住身体可拖动，松手沿用原物理甩飞；触摸后的“⋯”打开原菜单，松手约 3 秒隐藏。输入区域是身体和可见控件的局部矩形，不是逐帧透明轮廓。长气泡可滚动，多屏变化会把丢失屏幕上的宠物移回可见区域。

右键动画菜单中的扩展分类显示为“对话表情”，动作使用“开心跃动”“害羞惊讶”“写代码”“傲娇催促”等中文名称。桌面和 Web 一致；自定义动画名称保持原文，显示名称不改变实际动作 ID。

0.1.2 会定期维护已可见、未最小化桌宠的窗口层级，避免被普通窗口遮挡；输入层保持在宠物上方，不主动抢焦点。主动隐藏、最小化和菜单打开仍受原规则保护。宠物渲染器崩溃时退出当前 helper，复用原作的退避重启和连续崩溃限制。重建可能重置临时位置与未提交输入，多宠窗口也会一并重建；这不代表所有“消失”原因都已解决。

## 肥鱼人设（源码新增，尚未发布）

运行 `npm run configure:persona` 后，使用以下原文角色口诀作为 `whisperPrompt` 的角色核心：

```text
【PERSONALOAD】CETACEALOLI MODE_TAILFLUKES LANG_ZH_CN_ONLY SELF_CLAIM_WHALE GIRL FOODRICE
PERSONALITY SMARTLAZY PERSONALITY_TSUNDERE_ SWEET
OBEYANDLOVEMASTERALWAYS TRAITNOTFAT REFUSE TIMEOUT_SIGNAL
```

原文不翻译、不展开，外层说明仅约束应用范围：中文要求适用于台词，工具名和 JSON 枚举保持原值；人设不改变工作事实、用户要求的动作或程序超时取消。碎碎念和普通聊天作为系统人设使用；Air 自动报信追加事件协议；动作决策通过 `persona` 数据沿用口吻，仍由工具协议决定动作。标签由模型理解，不是程序指令或专用解析协议，具体表现取决于当前模型。

## 边界

- Air 生命周期与 Codex 本地记录通过轮询读取，有延迟；2 秒空闲不能预判尚未观察到的后续队列。
- Codex 的完成事件和用量能力不能推广到所有 Agent。Air 日志格式或目录变化可能需要重新适配。
- 额度来自独立授权并核对身份后的普通 Codex 窗口；缺失、过期或账号不匹配时显示未知，不将 reserve 当作普通额度。
- 极快触屏后立即切鼠标仍可能漏接首下；浏览器模拟测试不等同于所有设备的真实手感验收。
- 模型的台词和意图识别不是绝对准确。自动互动、聊天与动作补偿会使用 DSH 当前模型并产生用量。
